## 依存関係
```
P0 ─▶ P1 ─┬─▶ P2 ─▶ P6(保存ダイアログ)
          ├─▶ P3
          └─▶ P4 ─▶ P5 ─▶ P6(OS強制モード)
```
- P2 の提案エンジンは P1 のインデックスを利用
- P5 のユーザー別容量は P4 のクォータ判定を拡張
- P3 と P4 は並行開発可能

## 着手時の最初のタスク（P0〜P1 前半）
1. `dotnet new` で 01 §2 のプロジェクト群を作成、WinUI 3 テンプレート（Windows App SDK 1.6+）
2. `FileBox.Data` に 03 のスキーマとマイグレーション
3. `FileBox.Indexer` で MFT 列挙 → メモリ索引 → 前方一致/部分一致検索のプロトタイプを先に作り、性能を計測（最大の技術リスクのため最優先）
4. Named Pipe IPC で App から検索できるようにする
5. フォルダビュー（仮想化 ListView）＋タブ＋分割ペイン

## 実装時に設計から変えた点
- **保存先の重み**（02 §1.3）: 学習 0.40 / 名前 0.30 / フォルダ名 0.10 / 拡張子 0.10 / 最近度 0.10。当初案では繰り返し選んだ保存先が一般語だけ一致するフォルダに負けたため
- **フォルダプロファイル**（03 folder_profiles）: DB に持たず、提案のたびに候補フォルダの中身から作る
- **候補から外す場所**: システム・アプリ内部に加え、`.` で始まるフォルダ、開発用の生成物（bin/obj/node_modules、Unity の Library 配下など）、今ファイルがある場所の配下
- **保存ダイアログ連携**（02 §1.2）: UI Automation ではなく WinEvent フック＋ウィンドウメッセージで実装（標準ダイアログならこれで足り、軽い）。ファイル名欄は ID 1001 の Edit。`Ctrl+Shift+Space` での表示切替は未実装（パネルの × で閉じる）
- **ブックマーク**（03 bookmarks）: system.db ではなく利用者ごとの user.db に保存（リンクはそれを作った人の PC で使う想定）
- **容量の集計**（02 §5.1）: 常時の差分集計ではなく、要求時に索引から配下を合計し 5 秒キャッシュ（ゾーン数は少ないため十分速い）
- **エクスプローラー置き換え**（02 §7.1）: 対象を実在のフォルダ（Directory）とドライブ（Drive）に限定。ごみ箱・コントロールパネルなどの仮想フォルダ（Folder）は奪わない（開けない場所で Windows 側の操作を壊さないため）
- **system.db の保護**: 管理者（またはサービス）の Indexer が作ると「管理者と SYSTEM のみ変更可・利用者は読み取り」にする。一般権限の Indexer は読み取り専用で開き、判定はできるが管理操作は「管理者として再起動」が必要
- **接続元の特定**: `NamedPipeServerStream.RunAsClient` は偽装が後続処理に残り DB に書けなくなったため、トークンを開く間だけ偽装して必ず元に戻す実装にした
