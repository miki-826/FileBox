# 02. 機能設計

---
## 1. スマート保存（R1, R2）

### 1.1 入口（3系統）
| 入口 | 内容 | フェーズ |
|---|---|---|
| ① FileBox 内の保存/移動 | FileBox で「新規作成」「移動」「別名保存」時に提案パネルを表示 | P2 |
| ② 受け取りボックス | ダウンロード・デスクトップ・スクリーンショット等の監視フォルダに新着ファイルが来たら、振り分け候補をトースト＋一覧で提示 | P2 |
| ③ 他アプリの「名前を付けて保存」 | コモンファイルダイアログを UI Automation で検知し、ダイアログ横にサジェストパネルを重ねて表示。選択するとダイアログのファイル名欄にフルパスを入力 | P6 |

### 1.2 入口③の動作詳細
```
UIA: WindowOpenedEvent を購読
  → ClassName="#32770" かつ ファイル名ComboBox(AutomationId=1001) を持つ保存ダイアログを判定
  → ファイル名欄の ValueChanged を購読（入力のたび 150ms デバウンスで提案を再計算）
  → ダイアログの右側にトップモストのサジェストパネル（小ウィンドウ）を配置
  → 候補クリック: ファイル名欄に「<フォルダ>\<ファイル名>」を ValuePattern.SetValue
     （新規フォルダ提案の場合は先にフォルダを作成）
  → 保存完了（ダイアログ Close + ファイル出現をインデックスで確認）→ 学習
```
- 検知できないアプリ（独自ダイアログ）は②受け取りボックスで後から振り分ける運用で補完。
- パネルは `Ctrl+Shift+Space` で表示/非表示切替。

### 1.3 保存先推定アルゴリズム（ローカル）
**入力**: ファイル名、拡張子、（あれば）保存元アプリ名、現在時刻
**出力**: 候補フォルダ上位3件＋確信度、および新規フォルダ提案

1. **トークン化**
   - 区切り: 空白 `_ - . ( ) [ ]`、CamelCase 境界、数字⇔文字の境界
   - 日付検出: `20261018`, `2026-10`, `R8`, `令和8年` → `{年:2026, 月:10}` として別扱い
   - 日本語: 形態素解析は使わず、文字種境界での分割＋文字 2-gram（辞書不要・高速）
   - 正規化: 全角半角統一、大小文字統一、かな⇔カナ統一
   - 例: `2026年10月_請求書_山田商事.pdf` → `{請求書, 山田商事, 請求, 求書, ...}`, 日付=2026/10, ext=pdf
2. **候補収集**: 名前索引から、トークンを含むファイルを持つフォルダ／トークンを名前に含むフォルダを収集（上限 500）
3. **スコアリング**（各候補フォルダ f）
   ```
   score(f) = 0.30 * 名前類似度   (フォルダプロファイルとの TF-IDF コサイン類似度)
            + 0.40 * 学習スコア   (save_history: 似たトークン→f が選ばれた回数, 半減期60日。提示して選ばれなかった1位はマイナス)
            + 0.10 * フォルダ名一致 (トークンがフォルダ名・祖先フォルダ名に含まれるか)
            + 0.10 * 拡張子傾向   (f 内の同拡張子の割合)
            + 0.10 * 最近度       (f への最終書込の新しさ)
   ```
   - 実装時の調整: 当初案（名前0.40/学習0.25/フォルダ名0.15）では、同じ保存先を繰り返し選んでも一般語（「請求書」など）だけが一致するフォルダに負けたため、学習を最も強い手掛かりとした
   - フォルダプロファイルは DB に保持せず、提案のたびに候補フォルダ直下のファイル名から作る（常に最新・候補は最大60件なので十分速い）
   - 重みは設定ファイルで調整可能。除外フォルダ（Windows, Program Files, AppData, node_modules 等）は候補にしない
4. **確信度**: 1位スコアと2位スコアの差、絶対値から「高/中/低」に分類
5. **日付サブフォルダ補正**: 1位フォルダ配下に `2025`, `2026` や `01月` のような日付命名規則があれば、ファイル名の日付に合わせて下位フォルダまで掘り下げて提案（存在しなければ新規作成提案）

### 1.4 「なさそうだけど…」新規フォルダ提案
次のいずれかで発動:
- 1位の確信度が「低」
- 共通の上位概念はあるが、具体名に一致するフォルダがない（例: `請求書` フォルダはあるが `山田商事` 用がない）

**提案生成**:
1. 上位候補群の **共通の親フォルダ** P を求める（最も多くの候補を含む最下位祖先）
2. P 直下の兄弟フォルダの命名パターンを解析（例: 取引先名 / `YYYY` / `YYYY-MM` / `案件_xxx`）
3. ファイル名トークンのうち P の兄弟名の「型」に合うものを新フォルダ名にする
   - 例: `請求書\` 配下が `A商事\`, `B工業\` → 新フォルダ `請求書\山田商事\` を提案
4. 表示: 「該当フォルダはなさそうです。`D:\書類\請求書` に `山田商事` フォルダを作成して保存しますか？」 [作成して保存] [名前を変更] [別の場所]

### 1.5 学習
- 確定した保存先を `save_history` に記録（トークン集合、拡張子、保存元アプリ、フォルダ）
- 提案を無視して別の場所を選んだ場合も「正解」として記録（ネガティブ学習: 提示したが選ばれなかった候補の学習スコアを微減）
- フォルダプロファイルはインデックス変更イベントで差分更新

### 1.6 受け取りボックス
- 監視対象: 既定でダウンロード・デスクトップ（設定で追加可）
- 新着ファイル（書込完了＝5秒間サイズ不変）ごとに推定を実行
- 確信度「高」かつ「自動振り分け」ON のルールに合致すれば自動移動（Undo 可能・通知）
- それ以外は一覧に「推奨先」付きで並べ、ワンクリック or 一括で移動
- ルール: 「拡張子/名前パターン/保存元 → フォルダ」をユーザーが定義可能（学習結果からルール化を提案）

## 2. 複数ファイル同時表示（R3）

### 2.1 レイアウト
- **タブ**: WinUI `TabView`。タブごとに独立したペインツリー
- **分割ペイン**: 1タブ内を最大4ペイン（左右・上下・田の字）。境界ドラッグでサイズ変更、タブ/ファイルをペイン端にドラッグして分割
- **ペイン種別**: フォルダビュー（詳細/アイコン/タイル） / プレビュー / 検索結果
- **リンク表示**: フォルダビューで選択したファイルを隣のプレビューペインに自動表示（ペイン同士を「連動」設定）

### 2.2 プレビュー
| 種別 | 方式 |
|---|---|
| 画像 (jpg/png/gif/webp/heic/svg) | WinUI Image（HEICはWICコーデック） |
| テキスト・コード | 読み取り専用テキストビュー（シンタックスハイライト、10MB以上は先頭のみ） |
| PDF / HTML / Markdown | WebView2 |
| 動画・音声 | MediaPlayerElement |
| Office・その他 | 登録済み `IPreviewHandler` をホスト（エクスプローラーと同じ） |
| 未対応 | アイコン＋プロパティ表示 |

### 2.3 ワークスペース
- 現在のタブ・ペイン構成・各ペインの場所・選択ファイルを名前付きで保存
- 起動時に前回のワークスペースを復元（設定）
- ワークスペースにも `filebox://workspace/<id>` リンクを発行可能（予定表連携）

## 3. 高速・多様な検索（R4）

### 3.1 インデックス構築
| 対象 | 方式 | 目安 |
|---|---|---|
| NTFS ローカルボリューム | MFT 列挙（`FSCTL_ENUM_USN_DATA`）で全エントリのファイル参照番号・親参照番号・名前を一括取得 → 親子関係からパス復元 | 100万件 ≈ 10〜20秒 |
| 変更追従 (NTFS) | USN ジャーナル（`FSCTL_READ_USN_JOURNAL`）を常時読み、作成/削除/リネームを反映 | 遅延 < 1秒 |
| FAT/exFAT/ネットワーク | 初回再帰走査（並列 `FindFirstFileEx` + `FIND_FIRST_EX_LARGE_FETCH`）+ FileSystemWatcher | 低速だがバックグラウンド |
| サイズ・更新日 | MFT 列挙では取得できないため、名前索引構築後にバックグラウンドで段階取得（表示中フォルダ優先） | — |

起動時はスナップショットを読込 → 保存時点の USN 以降の差分のみ適用（数秒で検索可能に）。ジャーナルが切れていたら再構築。

### 3.2 メモリ索引構造（Indexer 内）
```
EntryTable  : 構造体配列 [id] → { parentId, nameOffset, nameLen, flags(dir/hidden/system), size, mtime }
NameHeap    : 正規化済み名前を連結した UTF-16 バッファ（文字列オブジェクトを作らない）
SortedByName: 名前順の id 配列        → 前方一致・完全一致を二分探索 O(log n)
Trigram     : 3-gram → id のポスティングリスト（圧縮）→ 部分一致を候補絞り込み後に検証
DirOnly     : フォルダのみの id 配列   → フォルダ名検索を約1/10の母数で実行
ReadingKey  : 名前のローマ字/ひらがな読みキー（あいまい検索用、かな⇔ローマ字変換）
```
- 100万件で約150〜250MB を想定（05 の目標参照）

### 3.3 検索モード
| モード | 処理 | 備考 |
|---|---|---|
| フォルダ名のみ | DirOnly を対象 | 最速 |
| ファイル名のみ | ファイルのみ対象 | |
| 前方一致 (先頭N文字) | SortedByName 二分探索 | `^abc` |
| 部分一致 | Trigram 絞り込み → 検証 | 既定 |
| 完全一致 | 二分探索 | `"abc.txt"` |
| ワイルドカード | `* ?` をパターン化、固定部分で Trigram 絞り込み | `report_*.xlsx` |
| 正規表現 | リテラル部分で絞り込み可能なら Trigram、不可なら全走査（並列） | `regex:` |
| あいまい | ReadingKey 照合＋編集距離≤2 | ローマ字入力で日本語名にヒット (`seikyuu` → 請求) |
| パス検索 | フルパスに対し部分一致 | `path:書類\2026` |

### 3.4 クエリ構文
```
請求書 ext:pdf,xlsx size:>1MB modified:2026-10 in:"D:\書類" folder: -tmp
```
| 演算子 | 意味 |
|---|---|
| `folder:` / `file:` | フォルダのみ / ファイルのみ |
| `ext:` | 拡張子（カンマで OR） |
| `size:` | `>1MB`, `<100KB`, `10MB..1GB` |
| `modified:` / `created:` | `2026-10`, `today`, `thisweek`, `>2026-01-01` |
| `in:` | 範囲指定（そのフォルダ配下） |
| `-語` | 除外 |
| `語1 語2` / `語1 \| 語2` | AND / OR |
| `^` / `"..."` / `regex:` | 前方一致 / 完全一致 / 正規表現 |

GUI ではクエリバー下のチップ（フォルダのみ・前方一致・拡張子・期間 等）でも同じ条件を指定でき、テキストと双方向に同期。

### 3.5 応答性の工夫
- 入力ごとに前回検索をキャンセル（50ms デバウンス）
- 結果をチャンク（100件）でストリーミング、先頭チャンクを即表示
- 並び順: 完全一致 > 前方一致 > 最近使用 > 浅い階層 > 名前順
- 範囲指定時は「そのフォルダの子孫 id 集合」を親チェーン判定で絞り込み（パス文字列比較をしない）
- 検索履歴・保存済み検索（スマートフォルダ）

## 4. リンクで指定フォルダへジャンプ（R5）

### 4.1 URI 形式
| 形式 | 用途 |
|---|---|
| `filebox://open?path=D%3A%5C書類%5C請求書` | パス指定で開く |
| `filebox://open?path=...&select=report.pdf` | フォルダを開きファイルを選択状態に |
| `filebox://bookmark/7f3a9c` | ブックマーク（移動・リネームしても追跡） |
| `filebox://workspace/3` | ワークスペースを復元 |
| `filebox://search?q=請求書%20ext%3Apdf` | 検索結果を開く |

### 4.2 登録
- MSIX マニフェストの `uap:Protocol Name="filebox"`（非MSIX時は `HKCU\Software\Classes\filebox`）
- ブラウザから踏んだ場合も OS がアプリを起動（初回はブラウザの確認ダイアログ）

### 4.3 ブックマーク追跡
- NTFS ファイル参照番号（`FILE_ID_INFO`）＋ボリュームシリアル＋最終パスを保存
- 開く時: ファイルIDからインデックス上の現在パスを解決 → 見つからなければ最終パス → それも無ければ「移動/削除された可能性」と最終パスの親を開く

### 4.4 連携の使い方
- フォルダ/ファイル右クリック →「リンクをコピー」(Markdown形式 `[請求書](filebox://...)` / プレーン選択可)
- Google カレンダー・Outlook・Notion 等の予定本文に貼り付け → 予定からワンクリックで資料フォルダへ
- カレンダーアプリが `filebox://` をリンク化しない場合に備え、`https` ラッパー（ローカル `http://127.0.0.1:<port>/open?...` → 転送）を設定で有効化可能（既定OFF）

### 4.5 安全性
- URI 起動時はパラメータを厳密に検証（正規化後のパスのみ受付、UNC/デバイスパスは設定で許可したもののみ）
- **実行ファイル・スクリプト（.exe .bat .ps1 .lnk 等）は開かない**。フォルダを開いて選択するだけ
- 権限チェックで閲覧不可なら開かずメッセージ表示

## 5. 容量制限（クォータ）（R6）

### 5.1 クォータゾーン
- 「フォルダ＋上限容量」を登録（例: `D:\写真` 上限 200GB）。PC 全体（ボリューム単位）も可
- ゾーンは入れ子可。書き込み時は該当する全ゾーンで判定
- 使用量は Indexer の SizeAggregator が親方向へ差分集計（USN イベントでリアルタイム更新）

### 5.2 強制の仕組み
| 書き込み経路 | 動作 |
|---|---|
| FileBox 経由（保存・コピー・移動・受け取りボックス） | 実行前に `合計サイズ ≤ 残り容量` を判定、超過ならブロック（理由と空きの作り方を提示: 大きいファイル一覧・重複候補） |
| 他アプリによる書き込み | 防げないため監視で検知 → 80% で警告、100% 超過で強い警告通知＋超過分の整理を促す |
| OS レベルで厳密に防ぎたい場合 | オプション: NTFS ディスククォータ（ボリューム×Windowsユーザー）を管理画面から設定（`IDiskQuotaControl` COM / `fsutil quota`、管理者権限） |

### 5.3 表示
- サイドバーに各ゾーンの使用量バー、ステータスバーに現在フォルダの所属ゾーン
- 容量分析ビュー（フォルダ別ツリーマップ、大きいファイル Top100、古いファイル）

## 6. アカウント・権限（R7）

### 6.1 アカウント（Windows サインイン連携・ログインレス）
エクスプローラーの代替として使うため、**FileBox 独自のログイン操作は一切求めない**。

- **識別**: FileBox のアカウント = Windows のローカル/Microsoft/ドメインアカウント（SID で一意）。Windows にサインインした時点で FileBox にもサインイン済み
- **自動登録**: あるWindowsユーザーが初めて FileBox を起動すると、そのSIDで `users` レコードを自動作成し既定ロールを割り当て
  - Windows の Administrators グループのメンバー → 「管理者」ロール
  - それ以外 → 「一般」ロール（管理者が既定ロールを変更可能。家族の子ども用アカウントを「ゲスト」既定にする等）
- **ユーザー切替**: Windows のユーザー切替／サインアウトがそのまま FileBox のユーザー切替になる（FileBox 内に切替UIは持たない）
- **管理操作の再確認**: 権限・クォータ・ユーザー設定の変更時のみ、Windows Hello（`UserConsentVerifier`）または Windows 資格情報ダイアログ（`CredUIPromptForWindowsCredentials`）で本人確認。パスワードは FileBox に保存しない
- **共通データ**（アカウント・ロール・権限・クォータ）は `%PROGRAMDATA%\FileBox\system.db` に保存し、変更は Indexer サービス経由（管理者ロールのみ）
- Windows 上で削除されたアカウントは、管理画面で「孤立ユーザー」として表示し、データ（作成ファイルの所有記録・容量）を別ユーザーへ引き継ぎ可能

### 6.2 ロールと権限
| ロール | 既定権限 | 既定容量 |
|---|---|---|
| 管理者 | 全操作・ユーザー/クォータ管理 | 無制限 |
| 一般 | 許可フォルダの閲覧・作成・編集・削除・リンク発行 | 50GB |
| ゲスト | 許可フォルダの閲覧のみ | 0（書込不可） |
| カスタム | 任意に組み合わせ | 任意 |

- 権限フラグ: `Read / Create / Modify / Delete / Share(リンク発行) / Admin`
- 対象: フォルダパス単位（配下に継承、明示的な拒否が優先）
- 判定順: ユーザー個別設定 → ロール設定 → 既定（拒否）
- **ユーザー別容量**: ユーザーが FileBox 経由で作成したファイルの合計（作成者を記録）、またはクォータゾーンを「ユーザーごと」に割り当て（例: `D:\Users\<名前>` を各 30GB）

### 6.3 強制範囲の明示
- FileBox の権限は FileBox 経由の操作にのみ効く（エクスプローラーからは迂回可能）
- 厳密な分離が必要な場合: FileBox ユーザーは既に Windows ユーザーと一致しているため、そのまま NTFS ACL とディスククォータを同時適用する「OS強制モード」をユーザー単位で ON にできる

### 6.4 監査ログ
- 保存・移動・削除・リネーム・リンク起動・権限/クォータ変更・初回利用（自動登録）・管理操作の本人確認 を記録
- 管理者は期間・ユーザー・操作種別で検索、CSV エクスポート

## 7. エクスプローラー置き換え統合（R8）

日常的にエクスプローラーの代わりに使えるよう、OS の「フォルダを開く」導線を FileBox に向ける。すべて**設定でオン/オフでき、オフにすれば即座に元のエクスプローラーへ戻る**こと。

### 7.1 置き換える導線
| 導線 | 方式 |
|---|---|
| フォルダのダブルクリック・「開く」（デスクトップ・スタートメニュー等から） | `HKCU\Software\Classes\Directory\shell\FileBox` と `Drive` に動詞を追加し既定に設定。HKCU のみ変更し HKLM は触らない。仮想フォルダ（`Folder`: ごみ箱・コントロールパネル等）は対象外でエクスプローラーのまま（実装時に変更、06 参照） |
| Win+E | 低レベルキーボードフック（Shell 常駐プロセス）で捕捉して FileBox を開く |
| 他アプリの「フォルダを開く」「場所を開く」(`ShellExecute` / `SHOpenFolderAndSelectItems`) | フォルダ動詞の置き換えで大半をカバー。`explorer.exe /select,` 直接呼び出しは置き換え不可（制約として明記） |
| タスクバーへのピン留め・スタートメニュー | 通常のアプリとして登録 |

### 7.2 エクスプローラー同等として最低限必要な機能
- ナビゲーション: 戻る/進む/上へ、アドレスバー直接入力（`%USERPROFILE%`, `shell:Downloads` 等の展開）、パンくず
- 特殊フォルダ: PC・ドライブ一覧・ネットワーク・ごみ箱・ライブラリ・OneDrive（Shell 名前空間 `IShellFolder` で列挙）
- ファイル操作: コピー/切り取り/貼り付け/削除/名前変更/新規作成/圧縮・展開（ZIP）、Undo、ドラッグ&ドロップ（他アプリとの相互）
- **シェルのコンテキストメニュー**: `IContextMenu` をホストし、7-Zip・VS Code など他アプリが追加した右クリック項目もそのまま使える
- サムネイル・アイコン: `IShellItemImageFactory`、オーバーレイアイコン（OneDrive の同期状態など）
- プロパティダイアログ: `SHObjectProperties` で標準のものを表示
- ネットワーク/ USB: ドライブの接続・取り外しをリアルタイム反映
- 起動の速さ: 常駐 Shell プロセスがウィンドウを事前生成し、フォルダを開く操作から表示まで 300ms 以内（05 参照）

### 7.3 安全策
- FileBox が起動できない・応答しない場合（2秒タイムアウト）は自動で `explorer.exe` にフォールバック
- アンインストール時・置き換えオフ時はレジストリを完全に元へ戻す（変更前の値を保存）
